# Data Structures and Algorithms - Study Notes
Sample study notes written for the GapFinder AI demo. Original content.

## 1.1 Array representation and indexing
An array stores its elements in one contiguous block of memory, and every element occupies the same number of bytes. Because of this layout, the address of any element can be computed directly: address of element i equals the base address plus i multiplied by the element size. This address arithmetic is why reading or writing an element by its index takes constant time, O(1), regardless of how large the array is. Most languages use zero-based indexing, so the first element is at index 0 and the last element of an array of length n is at index n - 1. Accessing index n is an out-of-bounds error. A static array has a fixed capacity chosen when it is created. A dynamic array grows by allocating a larger block, usually double the previous capacity, and copying the existing elements across.

## 1.2 Cost of array operations
Searching an unsorted array for a value requires a linear scan that may inspect every element, so it takes O(n) time. If the array is sorted, binary search repeatedly halves the search range and finds a value in O(log n) time. Inserting an element at the end of a dynamic array is amortized O(1): most appends are cheap, and the occasional resize that copies all elements is spread across many appends. Inserting or deleting at the front or in the middle costs O(n) because every element after the position must shift by one place to keep the storage contiguous. This shifting cost is the main weakness of arrays compared with linked lists.

## 1.3 Two-pointer and sliding-window techniques
The two-pointer technique keeps two indices that move through a sequence instead of using nested loops. For example, to find a pair with a given sum in a sorted array, start one pointer at the left end and one at the right end. If the current sum is too small, move the left pointer right; if it is too large, move the right pointer left. Each pointer moves at most n times, so the whole scan is O(n) instead of the O(n^2) cost of checking every pair. A sliding window maintains a contiguous range of elements and updates a running value as the window moves. When the window slides one position, add the entering element and subtract the leaving element rather than recomputing the whole window. This turns the maximum sum of k consecutive elements into an O(n) computation.

## 2.1 Singly linked lists
A singly linked list is a chain of nodes. Each node stores a value and a reference, called next, to the following node. The list is reached through a head pointer that refers to the first node, and the last node's next reference is null. Unlike an array, the nodes do not need to be contiguous in memory, so there is no address arithmetic. To reach the k-th node you must start at the head and follow k next references, which makes access by position O(n). Traversal visits each node once by following next references until null is reached. Every node carries the extra memory cost of its next reference.

## 2.2 Insertion and deletion in linked lists
Inserting a new node at the head of a singly linked list takes O(1) time: set the new node's next to the current head, then move the head pointer to the new node. Inserting after a node you already hold a reference to is also O(1), because only two references change and no elements shift. However, inserting at a position given only by its index costs O(n), since the list must first be walked to find that position. To delete a node from a singly linked list you need a reference to the node before it, so that its next can skip over the removed node. Forgetting to update the head pointer when deleting the first node is a common bug.

## 2.3 Doubly and circular linked lists
In a doubly linked list each node stores both a next reference and a prev reference. The backward link allows traversal in both directions and lets you delete a node in O(1) time when you hold a reference to that node, because its predecessor is available through prev. The cost is extra memory for the second reference in every node and more pointer updates on each insertion. In a circular linked list the last node's next reference points back to the first node instead of null. A traversal of a circular list must therefore stop when it returns to its starting node, otherwise it loops forever. Circular lists suit round-robin scheduling, where items are visited in a repeating cycle.

## 3.1 Stacks
A stack is a collection that follows last-in, first-out order, often abbreviated LIFO: the element removed is always the one added most recently. Push adds an element to the top, pop removes and returns the top element, and peek reads the top element without removing it. All three operations run in O(1) time when the stack is implemented with a dynamic array or a linked list. Calling pop on an empty stack is an underflow error, so implementations check whether the stack is empty first. Pushing onto a full fixed-capacity stack is an overflow. Stacks are used to implement undo features, to evaluate expressions, and by the language runtime to manage function calls.

## 3.2 Queues
A queue follows first-in, first-out order, abbreviated FIFO: elements leave in the same order in which they arrived. Enqueue adds an element at the rear and dequeue removes the element at the front. Both operations should run in O(1) time. Implementing a queue with a plain array by removing from index 0 is inefficient, because every dequeue shifts the remaining elements and costs O(n). A circular buffer avoids this by keeping front and rear indices that wrap around to the start of a fixed-size array. A linked list with both head and tail pointers also gives O(1) enqueue at the tail and O(1) dequeue at the head. A deque, or double-ended queue, allows insertion and removal at both ends.

## 3.3 Applications of stacks and queues
Bracket matching is a classic stack application. Scan the expression from left to right; push every opening bracket, and when a closing bracket appears, pop the stack and check that the popped bracket is the matching opener. The expression is balanced only if every closing bracket matches and the stack is empty at the end of the scan. Queues are the natural structure for processing items level by level. Breadth-first search places the starting vertex in a queue, then repeatedly dequeues a vertex and enqueues its unvisited neighbours, so vertices are processed in order of their distance from the start. Printer spoolers and task schedulers also use queues so that jobs are served in arrival order.

## 4.1 Tree terminology
A tree is a hierarchical structure made of nodes connected by edges, with no cycles. The single node without a parent is the root. A node with no children is a leaf. The depth of a node is the number of edges on the path from the root to that node, so the root has depth 0. The height of a tree is the number of edges on the longest path from the root to a leaf; a tree with only a root has height 0. In a binary tree every node has at most two children, called the left child and the right child. A tree with n nodes always has exactly n - 1 edges, because every node except the root has exactly one edge to its parent.

## 4.2 Binary search trees
A binary search tree, or BST, is a binary tree with an ordering property: for every node, all keys in its left subtree are smaller than the node's key and all keys in its right subtree are larger. To search, start at the root and compare the target with the current key, moving left if the target is smaller and right if it is larger, until the key is found or an empty position is reached. Insertion follows the same path and attaches the new key where the search ended. Search and insertion take time proportional to the height of the tree. In a balanced BST the height is O(log n), but inserting keys in already sorted order produces a degenerate tree shaped like a linked list, and operations then take O(n) time. Self-balancing trees such as AVL trees keep the height logarithmic.

## 4.3 Tree traversals
A traversal visits every node of a tree exactly once. Preorder traversal visits the node first, then its left subtree, then its right subtree. Inorder traversal visits the left subtree, then the node, then the right subtree. Postorder traversal visits both subtrees before the node, which makes it suitable for deleting a tree or evaluating an expression tree. An inorder traversal of a binary search tree outputs the keys in sorted ascending order. Level-order traversal visits nodes level by level from the root downwards and is implemented with a queue rather than recursion. Preorder, inorder and postorder are depth-first traversals and are naturally written recursively.

## 5.1 Graph representations
A graph consists of vertices and edges connecting pairs of vertices. An adjacency matrix for a graph with V vertices is a V by V table where entry (i, j) records whether an edge joins vertex i and vertex j. It answers the question of whether an edge exists in O(1) time but always uses O(V^2) memory, even when there are few edges. An adjacency list stores, for each vertex, a list of its neighbours, using O(V + E) memory where E is the number of edges. Adjacency lists are preferred for sparse graphs, where E is much smaller than V^2, and make it efficient to iterate over the neighbours of a vertex. In an undirected graph each edge appears in the lists of both of its endpoints.

## 5.2 Breadth-first search
Breadth-first search, or BFS, explores a graph outward from a source vertex in layers. It uses a queue: enqueue the source and mark it visited, then repeatedly dequeue a vertex and enqueue each neighbour that has not yet been visited. Vertices must be marked as visited when they are enqueued, otherwise the same vertex can be added to the queue several times. Because vertices are discovered in order of increasing edge count from the source, BFS finds the shortest path, measured in number of edges, in an unweighted graph. With an adjacency list, BFS runs in O(V + E) time. BFS does not give correct shortest paths when edges have different weights; that requires an algorithm such as Dijkstra's.

## 5.3 Depth-first search
Depth-first search, or DFS, follows one path as deeply as possible before backtracking to try other branches. It can be written recursively, where the call stack keeps track of the path, or iteratively with an explicit stack. Like BFS, DFS visits every vertex and edge once and runs in O(V + E) time with an adjacency list. DFS is used for cycle detection: in a directed graph, finding an edge to a vertex that is still on the current recursion path, called a back edge, proves that the graph contains a cycle. DFS is also the basis of topological sorting of a directed acyclic graph and of finding connected components.

## 6.1 Base case and recursive case
A recursive function solves a problem by calling itself on smaller instances of the same problem. Every correct recursive function needs a base case, which returns an answer directly without recursing, and a recursive case, which reduces the problem and calls the function again. Each recursive call must make progress towards the base case. For example, factorial(n) returns 1 when n is 0, which is the base case, and otherwise returns n multiplied by factorial(n - 1). If the base case is missing or can never be reached, the function keeps calling itself until the program runs out of stack space.

## 6.2 The call stack
Every function call pushes a stack frame onto the call stack. The frame holds the call's parameters, its local variables and the return address. When the call finishes, its frame is popped and execution resumes at the return address. A recursive function with recursion depth d therefore uses O(d) stack space, even if it allocates no other memory. Because the call stack has a limited size, very deep recursion causes a stack overflow error. This is why missing base cases crash programs, and why a recursive solution that recurses once per element of a large input may fail where a loop succeeds.

## 6.3 Recursion versus iteration
Any recursive algorithm can be rewritten iteratively, usually with a loop and, when needed, an explicit stack that replaces the call stack. Iteration avoids the overhead of function calls and the risk of stack overflow. Some recursive definitions repeat work: the naive recursive Fibonacci function recomputes the same values many times and takes exponential time. Memoization fixes this by storing the result of each subproblem the first time it is computed and returning the stored value on later calls, which reduces Fibonacci to O(n) time. Tail recursion, where the recursive call is the last action of the function, can be converted into a loop directly.
